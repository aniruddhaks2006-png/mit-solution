# Post-Award Contract Change Monitoring System

## Problem

Public contracts are evaluated in detail before award, but projects change substantially during execution. Contractors or subcontractors change, materials or costs shift, timelines are revised. When changes are hard to track against the original commitment, authorities cannot tell whether the project remains aligned with what was approved — and whether a change warrants scrutiny.

## Proposed solution

A decision-support dashboard that continuously compares each contract's **baseline commitment** (as awarded) with **current project information** during execution, detects **significant variations**, links them to **supporting evidence**, and assigns a **review priority** — without assuming every change is improper.

The system detects and represents:

- **Cost variance** — approved value rising above the awarded value
- **Schedule variance** — revised completion vs the baseline completion date
- **Contractor/subcontractor substitution** — who is delivering vs who was awarded
- **Material / scope variance** — bills of quantities drifting from baseline
- **Evidence completeness** — change orders that cite documents not actually attached
- **Change-order frequency** — amendment patterns that warrant closer review

## Variation model (what counts as "meaningful")

A change is surfaced when it crosses an explicit threshold (all configurable):

| Variation | Threshold |
|---|---|
| Cost overrun | approved value > +10% vs award |
| Schedule slippage | > 30 days late |
| Contractor substitution | any contractor change |
| Material/scope change | a single pay item changes > +15% |
| Evidence gap | any referenced change document missing |

## Review priority (explainable weighted score)

- 35%: cost variance
- 25%: schedule slippage
- 20%: contractor/subcontractor substitution
- 10%: material / scope variance
- 10%: evidence gap

Floor rules guarantee that a contractor substitution or an evidence ratio < 50% always triggers at least a Medium-priority review. The score is shown alongside the concrete reasons, so an officer can read *why* a contract was flagged.

## Layout and reasoning output

For every contract the dashboard shows a **baseline vs current** comparison and a human-readable reasoning list, for example:

- "Approved value is 38% above the awarded value (was ₹96 cr, now ₹132.5 cr)."
- "Completion slipped 165 days vs baseline (-25% of planned duration)."
- "Contractor substituted: Akshaya Constructions → Nandi Builders."
- "Bill of quantities deviates from baseline by up to 32% on one pay item."
- "2 of 4 referenced change document(s) are missing — additional evidence required."

The system is **not an accusation engine**. A flagged variation simply means *"this change is large enough that someone should confirm it is justified and recorded"*. Most variations are legitimate; oversight is about visibility, not presumption.

## Data

The demo uses synthetic data generated by `backend/data_generator.py`:

- 12 contracts across PWD, Urban Development, Health, Water, Power and Rural agencies
- baseline materials (bill of quantities) per contract
- change orders / amendments with type, value/day deltas, and evidence status
- monthly cumulative approved-value history vs the awarded baseline

Embedded scenarios cover stable projects (control), cost overruns, schedule slippage, contractor substitution with scope revisions, and evidence gaps.

## Running locally

### Backend

```bash
cd backend
python -m pip install -r requirements.txt
python data_generator.py
uvicorn main:app --reload
```

Backend: `http://localhost:8000`

### Frontend

```bash
cd frontend
npm install
npm run dev
```

## Demo story

1. Start on the table: a few contracts stand out with High priority.
2. Open a cost-overrun contract → value curve climbs away from the award line.
3. Open a contractor-substitution contract → contractor changed, reasoning bar explains it.
4. Open a contract with an evidence gap → "X of Y documents missing".
5. Show a stable contract → flagged Low, "no significant variation".

## Production considerations

- Ingest real procurement portals and e-tendering change-order feeds instead of synthetic snapshots.
- Add OCR / document hash linkage so evidence is verifiable, not self-reported.
- Add forecasting (likely final cost / completion date) and population-served weighting.
- Add drill-down to original tender documents and approvals ledger.
- Keep the neutral language: flag for review, never presume impropriety.
