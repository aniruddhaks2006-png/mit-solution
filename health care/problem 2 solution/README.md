
# From One Empty Shelf to a Regional Shortage

## Problem

A medicine shortage can begin at one facility and become regional when several facilities experience rising demand, delayed replenishment, low inventory, or geographic access constraints. A useful system must detect the early signal, estimate how soon stock could become critical, identify other facilities that can share surplus, and communicate uncertainty.

## Proposed solution

This project is a regional medicine supply early-warning dashboard.

It combines:
- Current stock on hand
- Historical consumption
- Recent demand acceleration
- Expected days of stock remaining
- Facility location
- Potential donor facilities
- Geographic distance

The system does not wait for a facility to reach zero inventory. It calculates **days of stock remaining** from recent consumption and flags facilities whose projected stock is becoming critical.

### Risk model

The demo uses an interpretable weighted risk score:

- 55%: stockout proximity
- 30%: demand acceleration
- 15%: low inventory relative to normal stock

This is intentionally explainable for a healthcare decision-support prototype. A production system could replace or augment this with a trained time-series forecasting model.

## How the system detects a regional shortage

Example:

Facility A:
- 8 days of insulin remaining
- demand increasing 35%
- nearby Facility B has 52 days

Facility C:
- 11 days remaining
- demand increasing 25%

The system sees that multiple facilities are moving toward a shortage for the same medicine. It then searches for facilities with surplus stock and ranks possible redistribution opportunities using stock coverage and geographic distance.

### Key insight

A single low-stock facility is not necessarily a regional shortage.

The system looks for **correlated deterioration across facilities for the same medicine**.

## Redistribution

For every high-need facility, the system searches for donor facilities that:
- have more than 30 days of stock
- have the same medicine
- are geographically closer
- are not themselves at high risk

The prototype displays the best nearby donor opportunity.

In a real deployment, redistribution would also require:
- regulatory checks
- batch/expiry information
- cold-chain requirements
- transportation capacity
- facility approval
- minimum safety-stock constraints

The prototype intentionally does not execute real-world transfers.

## Uncertainty

The dashboard provides a confidence indicator and labels signals as Low, Medium, or High risk.

A high risk score means:

> “The available data suggests a high probability of an approaching stock problem.”

It does NOT mean:

> “A shortage will definitely occur.”

Real systems should account for missing data, reporting delays, emergency deliveries, sudden demand changes, and data quality.

## Data

The project uses synthetic data generated by `backend/data_generator.py`.

This avoids using real patient or hospital information and makes the demo reproducible.

The generated dataset contains:
- 8 facilities
- 5 essential medicines
- 120 days of inventory history
- daily consumption
- receipts/replenishment
- facility coordinates

A synthetic regional demand shock is included for selected medicines to demonstrate how an emerging disruption can be detected.

## Future ML improvements

The MVP uses an interpretable statistical risk engine. For a stronger production/hackathon version, add:

1. Time-series forecasting (Prophet, XGBoost, LightGBM or LSTM)
2. Probabilistic stockout date prediction
3. Regional graph model where facilities are nodes and transportation routes are edges
4. Multi-echelon supply-chain modeling
5. Replenishment lead-time prediction
6. Expiry-aware redistribution
7. Cold-chain constraints
8. Optimization model for allocating limited surplus
9. Alert prioritization based on population served and medicine criticality
10. Scenario simulation: “What happens if replenishment is delayed 7 days?”

## Running locally

### Backend

```bash
cd backend
python -m pip install -r requirements.txt
python data_generator.py
uvicorn main:app --reload
```

Backend runs at:

`http://localhost:8000`

### Frontend

Open another terminal:

```bash
cd frontend
npm install
npm run dev
```

Vite will show the local frontend URL.

## Demo story

A good presentation flow is:

1. Start with one facility whose stock is falling.
2. Show that its consumption is accelerating.
3. Show another facility developing the same problem.
4. Show the regional risk increasing.
5. Show a third facility with surplus.
6. Display the proposed redistribution route.
7. Explain that the system is an early-warning and decision-support tool, not an automatic procurement/transfer system.

## Responsible use

This is a decision-support prototype. It should not autonomously decide medical supply transfers. Human supply-chain professionals must verify inventory, expiry, regulatory, transportation, and clinical-priority constraints before action.
